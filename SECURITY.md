# Security Policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability.

Use the repository Security tab to submit a private vulnerability report when private reporting is available. If private reporting is unavailable, contact an organization owner through an established private business channel and provide the repository, affected version, reproduction steps, impact, and any known mitigation.

Do not include active credentials, client data, personal information, or exploit data beyond what is necessary to reproduce the issue.

## Supported versions

Private application repositories define their own supported versions. Public standards in this repository apply to the current default branch.

## Disclosure

Tiztel Software coordinates disclosure after validation and remediation planning. Public disclosure without authorization may expose users or client systems to avoidable risk.
